ReqBot — Consolidated UI Design Direction

One app shell, one home behavior, one wireframe per screen. Phase 22 scope and future-only work are labeled throughout.

1. App Shell

Persistent left sidebar, icon+label, 6 items — no top nav bar

Search, Compare, Evidence, Checklists, Corpus, System. Trace, Corpus document detail, and Checklist preview are drill-in routes reached by clicking through — they never appear in the sidebar. A sidebar scales cleanly as sections grow and keeps the work area wide, which matters for dense tables and side-by-side comparisons.

Status placement: a small status pill (dot + label) sits in the top-right of a thin top strip, present on every screen, linking to /system. It is always visible without competing with page content.

Breadcrumb behavior: the top strip shows a breadcrumb only on drill-in routes (e.g. Corpus / afi17-101.pdf, Corpus / afi17-101.pdf / Generate Checklist). Top-level sidebar destinations show no breadcrumb, just the page title in the content area — no redundant "Search / Search."

Route layout: /search, /trace/:reqId, /compare, /evidence, /corpus, /corpus/:docId, /checklists, /checklists/:docId, /system. (Future-only: /corpus/:docId/ingest-status, /jobs — see Future section.)

2. Home / Root Behavior

Root redirects straight to Search — no dashboard

Search is the highest-frequency task and the flagship CLI command (reqbot ask). A dashboard would either duplicate counts already on Corpus/System or invent metrics the service doesn't track. Redirecting / → /search means one fewer screen to design, build, and keep truthful, and it matches how a CLI-first tool's users already think: they open ReqBot to find something, not to look at a summary.

5. Implementation Boundary

Phase 22

  • App shell: sidebar, topbar, breadcrumb, status pill (WP-22.1)
  • Corpus rename + list (WP-22.1/22.2)
  • Corpus document detail (WP-22.2)
  • System health page (WP-22.2)
  • Checklist API — thin wrapper (WP-22.3)
  • Checklists generate screen (WP-22.4)
  • Checklist preview / export screen, read-only fields (WP-22.5)
  • Integration gate across all of the above (WP-22.6)

Future-only

  • Ingest / upload UI ("+ Add documents")
  • Job queue + job history screens
  • Editable checklist status/assessor_notes (blocked on regeneration/merge design)
  • Export history
  • XLSX export
  • Profile management UI (create/edit)
  • MCP tool surface (separate track, same nav concepts)
